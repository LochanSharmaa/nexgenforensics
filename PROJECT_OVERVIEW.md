## 1. Project Summary

**NexGen iMATCH** is a forensic facial recognition system intended for
investigative use. It does two core things:

1. **1:1 verification** — given two face images, produce a cosine similarity
   score and a same-person / different-person decision against a calibrated
   threshold.
2. **1:N identification** — search a probe face against an enrolled gallery and
   return ranked candidates.

Around that core it provides case management, subject records, an operator
audit trail, role-based auth, report generation, and a public marketing site
with a demo console.

The project's defining characteristic is that its accuracy claims are
**measured and separated by operating condition** rather than blended. Clean
benchmark accuracy (~99.8% LFW) and degraded surveillance-footage accuracy
(~82% TinyFace) are reported independently, because they differ by ~17 points
and describe different real-world situations.

**Stated posture:** results on degraded footage are investigative leads for
human review, not identifications. See `CLAIMS.md`.

## 4. Core Components

### `nexgen_engine/config.py`
- `ThresholdConfig` — **the single source of truth for decision thresholds**
  (`match`, `review`, `verify`; currently **0.2871 / 0.2153 / 0.2871**, raised
  from 0.20/0.15/0.20 on 2026-07-31 to control false matches — decision record
  and both calibration attempts in BENCHMARKS.md §5c).
  `imatch_api.core.config.Settings` and `nexgen_engine/api/service.py` both
  derive from it; no other copy may exist.
- `EngineConfig` — model pack, `device` (`auto` | `cuda` | `cpu`),
  detection size, `use_flip_tta`, embedding dim, nested quality/threshold/
  security/search config.

### `nexgen_engine/models/cuda_runtime.py`
Purpose: prevent silent CPU fallback.
- `prepare_cuda_dlls()` — registers CUDA 12 / cuDNN 9 DLL directories
- `init_cuda()` — initializes the CUDA context before any ONNX session
- `assert_face_analysis_providers(app, label)` — **raises** `GpuBindingError` if
  CUDA was expected but a sub-model bound CPU
- `detect_duplicate_onnxruntime()` — detects the CPU/GPU namespace collision
- In: a loaded `FaceAnalysis`. Out: `{model_name: provider}` or raises.

### `nexgen_engine/runtime.py`
- `detect_runtime_capabilities()` — probes for insightface/onnxruntime/opencv/
  faiss/torch; CUDA availability is confirmed by **building a real ONNX session**,
  not by reading `get_available_providers()`
- `resolve_providers(device)` — returns `(providers, effective_device)`;
  supports `auto`
- `EngineRuntime` — owns loaded models, hands out detector + recognizer

### `nexgen_engine/search/gallery_index.py`
- `GalleryIndex` — in-memory vector gallery, **sharded per tenant**; `search()`
  requires `tenant_id`, so no code path can compare across tenants
- `MatchResult` (`subject_id`, `score`, `metadata`), `SearchOutcome`
- Optional FAISS acceleration — **present but currently unused**

### `nexgen_engine/search/persistence.py`
- `BiometricStore` — SQLite as source of truth; embedding stored in the same
  transactional row as its metadata (no index/metadata desync)
- `TemplateCipher` — AES-256-GCM per row, key from `NEXGEN_TEMPLATE_KEY`;
  authenticated, so tampering raises rather than decrypting to noise
- `put_template()`, `iter_templates()`, `write_audit()`, `get_audit()`,
  `restore_into(store, index)`
- Schema versioned; refuses to open a file written by a newer schema

### `nexgen_engine/benchmarks/verification.py`
The measurement core.
- `load_pack()` / `decode_pack()` — read official InsightFace `.bin` protocol packs
- `evaluate_pairs(emb_a, emb_b, issame, ...)` — 10-fold CV; **threshold fitted on
  9 folds, applied to the held-out fold**
- `_best_threshold`, `_tar_at_far`, `_auc_eer` — unit-tested against
  known-answer cases
- Out: `VerificationResult` (mean±std accuracy, TAR@FAR, AUC, EER, per-fold)

### `nexgen_engine/training/train_pipeline.py`
- `ResNet50ArcFaceBackbone` — torchvision ResNet-50 → 512-d L2-normalized embedding
- `run_training(...)` — ArcFace loss, AdamW, cosine schedule; `drop_last=True`
  on the DataLoader (a leftover batch of size 1 crashes `BatchNorm1d`)
- Out: versioned checkpoint `runtime/checkpoints/arcface_ft_<tag>_<date>.pt`
- **Note:** initializes from ImageNet weights, not ArcFace weights (§9)

### `imatch_api/`
- `main.py` — `create_app()`; lifespan calls `init_database()` then
  `engine.warm_up()` (a load failure aborts startup by design)
- `api/routes/search.py` — `POST /api/imatch/search` (1:N),
  `POST /api/imatch/verify` (1:1), candidate listing and adjudication
- `api/routes/auth.py` — login, refresh, logout, me, user creation
- `api/routes/reports.py` — `GET /api/cases/{case_id}/report`
- `core/dependencies.py` — `Principal`, bearer/API-key auth, role guards, rate limits
- `core/config.py` — `Settings` (env prefix `NEXGEN_`), `resolved_jwt_secret()`,
  `resolved_template_key()`

### `nexgen_engine/security/` — honesty-critical
- `liveness.py` — passive single-frame heuristic (texture/moiré/colour spread).
  Self-reports `"method": "passive_single_frame_heuristic"`, `"certified": false`.
  **Not** presentation-attack detection.
- `deepfake_detector.py` — FFT smoothness + Nyquist checkerboard heuristic.
  Its own docstring states it is **not** a trained classifier.
- `template_encryption.py`, `morphing_detector.py`, `audit_logger.py` (hash-chained JSONL)

## 5. Data Flow

### 1:1 verification (implemented, tested end to end)
```
Two images (base64 JSON) + lawful_basis
      → POST /api/imatch/verify        [Bearer token required]
      → auth: Principal resolved (bearer or X-API-Key), rate limit
      → decode + size guard
      → FacialRecognitionPipeline.encode_bytes() per image
            → detection (SCRFD/RetinaFace)
            → 5-point alignment → 112x112 crop
            → quality report + liveness heuristic + deepfake heuristic
            → ArcFace embedding (+ optional flip-TTA) → L2 normalize
      → cosine similarity
      → compare to ThresholdConfig.verify
      → morphing check, explanation text
      → audit row written (hash-chained JSONL + queryable DB row)
      → VerifyResponse {similarity, verified, threshold, explanation,
                        reference/probe assessments, morphing, audit_hash, notice}
```

### 1:N identification
```
Probe image → same encode path → GalleryIndex.search(tenant_id, emb, top_k)
   → brute-force cosine over that tenant's shard only
   → subject-collapsed ranked candidates → audit row → response
```

### Enrollment + persistence
```
Image + identity_id
   → encode → template
   → BiometricStore.put_template()   [AES-256-GCM, single transactional row]
   → GalleryIndex.add(tenant_id, ...)
On startup: restore_into(store, index) rebuilds the in-memory index from SQLite.
```
**CONFLICT:** this persistence path is implemented and tested in
`nexgen_engine` (`tests_engine/`), but **is not wired into `imatch_api`**. See §9.

### Benchmarking
```
.bin protocol pack → decode → per-model embeddings (cached to
runtime/benchmarks/embeddings/) → fusion config → 10-fold CV
→ runtime/benchmarks/verification_results.json → BENCHMARKS.md
```

## 7. Setup Instructions

```bash
git clone <repo> && cd nexgenforensics
python -m venv .venv && .venv\Scripts\activate      # Windows
```

**GPU host (recommended)** — installs, removes the CPU/GPU onnxruntime
collision, then asserts CUDA actually bound:
```bash
python scripts/setup_gpu.py
```

**CPU-only host:**
```bash
pip install -r backend/requirements.txt -r backend/requirements-engine.txt -r backend/requirements-cpu.txt
```

**Create the first operator account** (required — no account exists by default,
and every biometric endpoint needs auth):
```bash
export NEXGEN_JWT_SECRET="$(python -c 'import secrets;print(secrets.token_urlsafe(64))')"
python backend/scripts/bootstrap_admin.py --password '<strong password>' \
    --email 'investigator@your-org.example' --role admin
```

**Run the API:**
```bash
python -m uvicorn imatch_api.main:app --host 127.0.0.1 --port 8443 --app-dir backend
```

**Frontend:**
```bash
cd frontend && npm install && npm run dev
```

**Verify the install:**
```bash
python scripts/verify_gpu.py                              # expect: PASS (all 12 checks)
cd backend && python -m pytest tests_engine/ -q            # expect: 10 passed
```

First startup downloads/loads InsightFace packs (~350 MB) and takes 30–60 s.

### Item 28 is re-scoped — do NOT just install faiss

The original framing ("FAISS-backed search") would not achieve its goal. The
existing branch in `gallery_index.py` builds `faiss.IndexFlatIP`, which is an
**exact** inner-product index — brute force with better SIMD. Installing faiss
would buy a constant factor, **not** a change in complexity; 100k templates
would still scale linearly.

Measured baseline (BENCHMARKS.md §7b): 1k → 0.207 ms, 10k → 1.087 ms,
100k → **15.98 ms**, i.e. at 100k the search costs about as much as encoding the
probe. Below ~10k there is nothing to win.

Real scaling needs an **approximate** index — IVF-PQ or HNSW — and the recall
loss that comes with it. That loss must be **measured and accepted explicitly**,
not assumed away: for a forensic system, a missed candidate from an ANN index is
an investigative lead that silently never surfaced. Benchmark at 1k / 10k / 100k
and report recall against exact search at each size.

### Deliberately not implemented

**Item 22 — enhanced-image rendering in reports.** `report_pdf.py`'s
`draw_enhanced_pair()` raises `NotImplementedError` on purpose. The constraint is
that an enhanced image may appear only when labelled *"AI-enhanced preview — not
evidentiary, for visual reference only"* **and** shown beside the unmodified
original. A partial implementation could render an enhanced image without that
pairing, which would breach the evidentiary rule, so it fails loudly instead.
Owner confirmed this is the correct state.

**Item 19 — Vercel deploy.** Blocked on infrastructure, not effort. There is no
deployed backend, `vercel.json`'s catch-all rewrite returns 405 on POST to a
static host, and its CSP `connect-src 'self' https:` blocks any `http://`
backend. A frontend-only deploy cannot work. Needs a hosted HTTPS backend first,
then `VITE_IMATCH_BASE_URL` and the CSP updated to match.

**Items 36–42 — fine-tuning.** Run to completion, with a **negative result**.
The contamination barrier was removed (692 of 10,572 CASIA identities excluded)
and the model was fine-tuned from ArcFace weights — not ImageNet — on degraded
imagery, with an identity-disjoint validation split and early stopping. It
scored worse on all six benchmarks, worst on TinyFace (82.45% → 79.38%). The
deployed model is unchanged and no claim is made for the checkpoint. This is a
measured outcome, not an unexplored gap. See BENCHMARKS.md §6c and §6d.

## Key environment variables

| Variable | Effect |
|---|---|
| `NEXGEN_JWT_SECRET` | **Set this.** Without it an ephemeral per-process secret is used and all tokens die on restart. |
| `NEXGEN_TEMPLATE_KEY` | Base64 32-byte AES-256 key. Without it templates are stored **unencrypted** (logged loudly). |
| `NEXGEN_ENGINE_DEVICE` | `auto` (default) / `cuda` / `cpu` |
| `NEXGEN_MATCH_THRESHOLD`, `NEXGEN_REVIEW_THRESHOLD`, `NEXGEN_VERIFY_THRESHOLD` | Override thresholds — re-run the benchmark for the deployed pack first |
| `NEXGEN_MODEL_ROOT` | Relocate the InsightFace model directory |
| `NEXGEN_FUSION_METHOD` | `single_glintr100` (default in `InsightFaceEnsembleBackbone`), `weighted_avg`, `dual_ensemble`, `concat`, … |
| `NEXGEN_FORCE_CPU`, `NEXGEN_REQUIRE_GPU` | Override GPU assertions |
| `VITE_IMATCH_BASE_URL` | Frontend API base (default `http://127.0.0.1:8443`) |
